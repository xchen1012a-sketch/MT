# API 契约规范

本规范约束 HTTP 接口格式，沿用 FastAPI 后端底座的直接响应方式。

## 路径与模型

- 业务 API 统一使用 `/api/v1` 前缀，OpenAPI 地址为 `/api/v1/openapi.json`。
- 请求与响应使用显式的 SQLModel/Pydantic 模型；字段名采用 `snake_case`，不在不同接口间自行切换大小写风格。
- 创建、局部更新、公开响应与数据库模型分开定义；公开响应不得包含密码哈希、设备密钥等内部字段。
- 每个路由声明业务 tag，操作名在同一 tag 下唯一，保持生成的 operationId 稳定；契约变更时同步更新调用方。
- 普通结构化请求使用 JSON；登录表单和显式声明的文件、HTML 等接口按各自媒体类型处理。

## 响应格式

| 类型 | 格式 |
| --- | --- |
| 单个资源 | 直接返回公开对象，不额外套 `data` |
| 分页列表 | `{"data": [], "count": 0}` |
| 操作提示 | `{"message": "..."}` |
| 业务错误 | 非 2xx 状态码及 `{"detail": "..."}` |
| 参数验证错误 | HTTP 422，`detail` 为包含 `loc`、`msg`、`type` 等信息的数组 |

- 不引入全局 `{success, data, errorCode, showType}` 包装，也不返回 HTTP 200 来伪装失败。
- 分页参数使用 `skip`、`limit`；`skip` 从 0 开始，沿用默认 `limit=100`。新列表必须声明非负偏移、正数条数及合理上限。
- `count` 表示授权范围内、应用相同过滤条件后、分页前的总条数；排序必须稳定，同值时增加唯一标识作为次序依据。
- 400 表示请求不符合业务规则，403 表示无权限，404 表示资源不存在，409 表示唯一性等冲突；已有认证状态码按认证规范处理。
- 健康检查等已有明确返回类型的基础接口保留自身契约，不为套用列表或对象格式而改写。

## 契约维护

- OpenAPI 由路由及模型生成，是客户端字段与类型的机器可读依据；不得手写另一份同名接口定义长期并行维护。
- 必填、可空、枚举、长度、范围、媒体类型和错误响应必须进入模型或路由声明，不能只写在注释里。
- 新增金融数据与时间字段必须遵守数据语义规范；示例、Mock、测试和客户端类型须与契约一致。
- 删除字段、改名、改变单位或响应层级属于破坏性变更，必须先明确变更及兼容方案，不能以修前端为由静默改后端。
