# 金融数据与时间语义规范

本规范是跨采集器、后端、前端的数据表达与计算口径规则，新增业务字段必须遵守。

## 跨端数据表达

| 数据 | API 表达 |
| --- | --- |
| UUID、MT5 登录号、订单号、成交号 | 字符串；不转为 JavaScript `number` |
| 金额、价格、数量、汇率、比例 | 十进制定点字符串，例如 `"1234.50"`；不携带货币符号或千分位 |
| 时间点 | RFC 3339 带时区字符串，统一输出 UTC，如 `2026-11-24T04:00:00Z` 或等价 `+00:00` |
| 自然日 | `YYYY-MM-DD`，必须明确其业务时区 |
| 计数、分页值 | JSON 整数，保证客户端安全整数范围 |
| 缺失与空集合 | 缺失标量使用 `null`；确认无记录的集合使用 `[]`；0 表示真实零值 |

- 此处的金融字段格式是 MT 新增业务契约，不表示上游模板已实现 MT5 金融模型。
- 不依赖框架默认序列化来保证格式；请求模型须验证有限十进制值，响应模型及 OpenAPI 须明确字符串格式，拒绝 NaN、Infinity 等无效值。
- 字段定义必须说明单位、正负方向、精度及舍入方式；比例采用 0～1 还是 0～100 必须明确，不由页面猜测。
- PATCH 中未传字段表示保持原值，显式 `null` 只在允许清空时成立；不能把两者合并处理。

## 时间与来源

- 统一保存 UTC 时间点；“当日”以 `Asia/Shanghai` 自然日计算，区间采用含起点、不含终点 `[start, end)`。
- 采样时间、业务事件时间、服务器接收时间各有含义，不能相互覆盖；来源时间必须先确认时区或时间戳单位。
- 原始值、后端派生值、人工调整分别可追溯；旧样本不能因为刚收到就变成最新采样。

## 财务计算

- 后端用 Decimal 统一计算，数据库用 NUMERIC 保存；从 SDK 浮点读数接入时，按明确的来源精度转为十进制，不直接用 `Decimal(float)` 扩散二进制误差。
- 当日净值变化为当前净值减日初净值，与交易盈亏分开；日初样本缺失返回缺失状态，不取任意日间读数冒充日初。
- 出入金、券商调整、人工记账与交易结果分类保留，禁止重复纳入盈亏；具体公式及费用覆盖范围必须在对应业务定义中明确。
- 不同币种不能直接相加；换算须保留原币、目标币、汇率来源、汇率时间和覆盖范围，缺汇率不能伪装完整汇总。
- 回撤、收益率及保证金等指标必须明确基准与分母；缺基准或分母为零时返回缺失及原因，不返回虚构的零。

序列化能力参考：[Pydantic 标准库类型](https://docs.pydantic.dev/latest/api/standard_library_types/)。上述业务表达是项目约束，须通过模型与接口样例验证。
