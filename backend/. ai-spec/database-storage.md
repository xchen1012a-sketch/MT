# 数据库存储规范

本规范约束 PostgreSQL、SQLModel/SQLAlchemy 与 Alembic 的数据落地方式。

## 类型与约束

| 数据 | 存储与建模规则 |
| --- | --- |
| 系统内部主键 | 沿用 UUID，Python 使用 `uuid.UUID`，数据库使用原生 UUID |
| MT5 登录号、订单号、成交号 | 作为外部标识保留原值；API 使用字符串，落库不得经过浮点转换；采用文本或经范围验证的整数类型 |
| 金额、价格、数量、汇率、比例 | Python 使用 `Decimal`，数据库使用显式 `NUMERIC(precision, scale)` |
| 时间点 | 带时区的 UTC `datetime`，数据库使用 `TIMESTAMP WITH TIME ZONE` |
| 自然日 | `DATE`，按业务规定时区从时间点推导，不能用日期代替采样时间 |
| 开关、状态 | 布尔使用 Boolean；多状态使用有固定允许值的字段及数据库约束 |
| 可缺失值 | 使用 NULL，不能以 0、空字符串或特殊日期代替 |

- 每个定点字段在建模时明确精度、范围和舍入方式，禁止统一假定所有金额两位小数；超范围应明确拒绝，不得静默截断。
- 时间列必须显式声明带时区的 SQLAlchemy 类型，不能仅凭 Python `datetime` 注解假定落库类型正确。
- 账户业务身份使用“券商服务器 + 登录号”，与系统 UUID 区分；在约定账户域内用数据库约束保证唯一，重复采集来源不能新建成可重复汇总的账户。
- 唯一性、外键、非空与必要的 CHECK 约束由数据库兜底，应用层先查询不能代替并发安全约束。
- 核心金融数据采用结构化字段；JSONB 仅保存有明确结构及用途的扩展或原始载荷，不能替代金额、时间与关联关系的建模。

## 事务与迁移

- 一次请求或后台任务使用独立 Session；业务上的原子操作在同一事务完成，失败整体回滚，不跨进程共享 Session。
- 多步骤业务由统一事务边界控制提交，不能让中间 CRUD 提前提交造成半成品；并发写入仍须依赖唯一约束及合适的锁或更新条件。
- 模型变化必须配套 Alembic 迁移，审查自动生成的列类型、索引和约束；不能在部署时用 `create_all` 代替迁移。
- 已在共享环境执行的迁移通过新增迁移修正，不能重写历史或删除重建数据库来同步模型。
- 金融历史、人工调整和审计的删除或级联规则必须显式确定，不能照搬模板中的普通资源删除行为。

类型依据：[SQLAlchemy 类型文档](https://docs.sqlalchemy.org/en/20/core/type_basics.html)。具体业务表及字段清单在各业务设计中维护，本规范不存表结构台账。
