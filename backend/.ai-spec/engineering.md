# 后端工程与验证规范

本规范约束后端组织、依赖和验证方式，以项目实际配置为准。

## 组织与依赖

- 使用 FastAPI、SQLModel/Pydantic、PostgreSQL、Alembic；运行版本遵守 `pyproject.toml`，不把采集器的 Python 要求直接套用到后端。
- 路由负责协议与依赖注入，数据访问负责持久化；跨步骤的金融计算、接收和告警逻辑形成可独立验证的业务函数，避免散落在路由或前端。
- 模型及响应必须有类型；已有模板中的 `Any` 不构成新增业务取消类型校验的理由。
- 使用 uv 管理依赖及正式 `uv.lock`，新增依赖须同步锁定；不以旧工作区锁文件或上游主分支作为构建依据。
- 配置由 Settings 与环境变量读取；密钥不入库，不能为了导出 schema 或运行测试而读取、打印真实凭据。
- 不因上游 README 提到 Compose、邮件源码等就假定本仓库已有对应能力；执行前核实所需资源与配置。

## 验证要求

- 类型及格式检查在后端目录运行 `uv run bash scripts/lint.sh`，涵盖 mypy、ty、Ruff 检查与格式校验。
- 后端测试使用 Pytest：`uv run bash scripts/test.sh`。必须连接隔离的测试 PostgreSQL，现有 fixture 会清理用户数据，严禁指向真实业务数据库。
- 数据库模型变更验证新库迁移及已有结构升级，检查 SQL 类型、约束与模型一致，不能仅依靠 Python 类型检查。
- 接口变更验证响应字段、HTTP 状态、媒体类型、授权及错误分支，并检查 OpenAPI 与客户端生成兼容性。
- 金融规则使用可复现样例验证缺失值、出入金、精度、跨币种和日界线；接收链路验证重复、乱序、重试及账户切换。
- 检查受环境限制未执行时明确说明，不能将“写了测试”或“文档约定”表述为“已经通过验证”。
