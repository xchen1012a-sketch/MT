# 登录会话与权限展示规范

认证协议以[后端认证规范](<../../backend/. ai-spec/auth-security.md>)为准，本规范约束浏览器会话行为。

## 登录与身份映射

- 登录按后端要求提交表单编码，不能沿用模板 JSON 登录或判断 `status === 'ok'`。
- 登录成功取得 token 后，再获取当前用户并刷新全局身份状态；不能只因表单提交成功就显示已登录。
- 全局用户身份通过 `getInitialState` 与 `useModel('@@initialState')` 共享，不在不同页面各维护一套登录用户。
- 公开用户映射为布局所需的视图字段时，在统一适配处处理，例如 `full_name` 到显示名称；不能要求后端返回模板的 `name`、`avatar`、`access` 全套字段。
- 管理员展示权限来自服务端 `is_superuser`，不能以演示账户名或浏览器自填的角色决定。

## 会话生命周期

- Bearer 凭据通过统一请求层附加；仅发送到授权的 MT 后端来源，不注入第三方请求。
- token 持久化位置与有效期策略须在会话实现前明确，全站复用；本规范不默认指定 localStorage、Cookie 或新增刷新接口。
- 注销时清除凭据、全局身份及该用户的请求缓存；不能调用后端未声明的演示退出接口，也不能声称本地注销已撤销服务端 JWT。
- 401 及确认失效的凭据触发统一登录恢复；403 先区分认证与授权，必要时通过当前用户查询确认，避免所有无权限操作都退出登录。
- 用户信息请求网络失败不能一律当作未登录；保留明确的加载失败或重试状态。
- 登录后的 redirect 只允许同源站内相对路径，防止开放重定向。

## 权限边界

- 路由和组件通过统一 access 能力控制展示；服务端始终独立授权，前端隐藏入口不构成安全边界。
- MT5 监控页面不出现下单、平仓、改单能力；合法管理操作仍按后端授权显示。
- 正式页面不得依赖演示用户、Mock token 或本地模拟角色作为真实认证依据。
