# 前端工程与验证规范

本规范约束依赖、代码生成及验证；命令以实际 `package.json` 和工具配置为准。

## 工程约束

- 使用 npm 与 `package-lock.json`，Node 版本遵守 engines；不引入 yarn/pnpm 锁文件并行维护依赖。
- TypeScript 保持 strict；接口类型与视图类型分清，不以 `any`、`@ts-ignore` 或复制可选字段逃避契约错误。
- Biome 负责 lint 和格式，TypeScript 负责类型检查，不另建 ESLint/Prettier 规则体系。
- 自动生成的 API 服务与 Umi 临时产物不手工修补；修正生成来源或适配层后重新生成。
- 上游 README、速查表及工具指南仅作参考；执行命令前核实脚本与资源，不能假定模板中的精简、部署或演示 Worker 仍存在。
- 固定经过验证的依赖版本；模板升级须明确范围并验证，不因上游有新版本自动覆盖业务代码。
- 环境变量及构建配置进入浏览器后可被读取，不能放入数据库凭据、签名密钥或服务端秘密。

## 验证要求

- 常规检查：`npm run lint`；构建检查：`npm run build`。
- 单元及组件测试使用 Vitest，`npm test`；当前配置使用 Playwright Chromium 浏览器环境，不能按上游旧文档配置 Jest。
- 端到端使用 `npx playwright test`；测试必须明确使用 Mock 还是真实 MT 后端，Mock 通过不能当作跨端验收通过。
- 修改 antd 组件运行 `npx antd lint ./src`，问题需定位到兼容用法，不能通过整体关闭规则解决。
- 请求对接验证原始对象、分页适配、FastAPI `detail`、认证与无权限、离线重试；数据展示验证 null/0、大整数标识、定点精度和北京时间日界线。
- 修改金融页面还须验证账户切换、乱序响应与过期提示；类型检查通过不能替代真实响应样例和必要的交互验证。
- 检查未实际执行或受环境限制时明确说明，不能仅凭文档更新宣称应用已经符合规范。
