# 页面、组件与样式规范

本规范沿用 Ant Design Pro / Umi Max / React / TypeScript 的组织方式。

## 页面与组件

- 页面通过 Umi 声明式路由注册；菜单名称与国际化 key 同步，权限通过统一 access 能力引用。
- 页面使用函数组件与 Hooks；页面专用组件、服务和类型就近组织，跨页面复用内容才提升为公共模块。
- 业务页面使用现有布局、PageContainer、Ant Design 和 ProComponents；不为一个功能引入第二套后台 UI 框架。
- 编写 antd 组件前查询安装版本对应的 API，例如 `npx antd info <Component> --format json`；不能照记忆或其他大版本猜属性。
- 表格、表单、图表均显式处理加载、空数据、错误与权限状态，关键操作具有明确反馈。
- 页面布局适配电脑和手机；表格可横向滚动但关键账户身份、状态与操作不能失去可访问性。
- 表单输入有标签，状态不只靠颜色表达，交互支持键盘操作。

## 状态与样式

- 用户与布局状态沿用 Umi 初始状态能力，轻量共享交互状态使用 `useModel`；服务端数据刷新遵守数据展示规范。
- Tailwind v4 用于布局，antd-style 用于主题 token，局部复杂样式使用 CSS Modules；Less 仅维护已有遗留样式。
- 颜色、间距、圆角优先复用主题 token，不在多个页面分别写死同一套主题值。
- 文案通过既有国际化机制维护，新增菜单和业务文案同步相关语言资源；不要在组件内维护另一套翻译表。
- 登录页、监控页的必要资源使用可控的本地或明确配置来源，避免因演示外链失效导致核心界面无法加载。
