# 金融数据展示与刷新规范

字段格式与计算含义以[后端数据语义](<../../backend/.ai-spec/data-semantics.md>)为准，数据新鲜度以[采集接收规范](<../../backend/.ai-spec/ingestion.md>)为准。

## 数据展示

- UUID、登录号、订单号、成交号保留字符串，不转 number、不加千分位，列表行使用稳定的业务唯一键。
- 金融值以定点字符串保留；不使用 JavaScript 浮点运算重算盈亏、收益率、汇率或账户汇总，派生业务值由后端提供。
- 金额按币种和已定义的精度格式化，不统一套人民币符号或两位小数；格式化不能修改原值，也不能把舍入后的文本回传覆盖数据。
- 图表仅在绘图边界将有限值转为 number，转换不能改变业务原值；精确提示、导出和对账仍使用原始定点值。
- `null` 显示缺失及适当原因，真实零显示 0；禁止 `value || 0`、`Number(null)` 等把缺失转换成零。
- 无记录、加载中、请求失败、离线和旧数据分别展示；已加载的旧值可以保留，但必须标明时间和过期状态。
- 时间点按约定时区显示，“当日”固定使用 `Asia/Shanghai`；不能随浏览器所在时区改变业务日，也不能直接截取 UTC 字符串生成北京时间日期。
- 日初缺失显示待确认；跨币种汇总显示目标币、换算依据与覆盖范围，不能隐藏未计入账户。

## 请求状态与刷新

- 服务端状态采用明确的查询层；需要共享缓存、轮询及失效管理时使用已接入的 React Query，同一资源避免多套重复缓存。
- 查询键包含影响结果的账户、筛选、分页和时间范围；切换账户时不能短暂将上一账户的数据标成新账户结果。
- 统一配置刷新节奏，离开页面释放轮询；避免并发重叠请求及旧响应覆盖新查询。
- 新鲜度使用服务端状态及原始采样时间判断，不能每次请求成功就标为“实时”。浏览器联网状态不能代表 MT5 在线。
- 同一时刻展示的数据须能说明对应的采样或聚合范围；筛选后的总数与汇总含义保持一致。
- 告警判断和通知由后端持续运行，浏览器只展示与提交经授权的确认操作，关页不得改变告警是否成立。
